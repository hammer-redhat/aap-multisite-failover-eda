# Issue-to-PR Automation Design

**Date:** 2026-07-27
**Repo:** hammer-redhat/aap-multisite-failover-eda

---

## Goal

When a GitHub issue is opened, an AI agent reads it, generates the necessary file changes (docs, config, Ansible YAML — whatever the issue calls for), and opens a draft PR. If that draft PR is closed without merging, the agent comments on the original issue to let the author know.

---

## Components

```
.github/
  workflows/
    pr-agent.yml       ← replaced: triggers on issues/opened
    pr-closed.yml      ← new: triggers on pull_request/closed (not merged)
scripts/
  generate_pr.py       ← new: two-step GPT-4o logic
```

No new runtime dependencies beyond the `openai` Python package.

---

## Workflow: pr-agent.yml

**Trigger:** `issues: [opened]`
**Runs on:** `ubuntu-latest`
**Timeout:** 10 minutes
**Permissions:** `issues: write`, `pull-requests: write`, `contents: write`
**Condition:** `github.event.sender.type != 'Bot'`

**Steps:**
1. Checkout `aap-26-failover` at HEAD
2. Install Python deps (`pip install openai`)
3. Run `python scripts/generate_pr.py` (id: `generate`)
   - Env vars passed in: `ISSUE_NUMBER`, `ISSUE_TITLE`, `ISSUE_BODY`, `GITHUB_TOKEN`, `OPENAI_KEY`
   - Script writes `changes_made=true` or `changes_made=false` to `$GITHUB_OUTPUT`
4. If `steps.generate.outputs.changes_made == 'true'`:
   - Create branch `ai-issue-{number}-{slug}`
   - Commit with message `ai: address issue #{number} – {title}`
   - Open draft PR: `gh pr create --draft`

---

## Workflow: pr-closed.yml

**Trigger:** `pull_request: [closed]`
**Condition:** `github.event.pull_request.merged == false && startsWith(github.event.pull_request.head.ref, 'ai-issue-')`
**Permissions:** `issues: write`

**Steps:**
1. Parse `Closes #N` from PR body
2. If issue number found, post comment on issue #N:
   > "Draft PR #{pr_number} was closed without merging. Open a new issue with updated requirements to try again."

---

## Script: scripts/generate_pr.py

### Call 1 — File Selection

**Input to GPT-4o:**
- System prompt: instructs the model to return a JSON array of file paths relevant to the issue
- User message: repo file tree (excluding `.git`, `screenshots`, `__pycache__`, `*.pyc`) + issue title and body

**Expected output:**
```json
["README.md", "vars/main.yml.example"]
```

### Call 2 — Edit Generation

**Input to GPT-4o:**
- System prompt: instructs the model to return a JSON array of file change objects
- User message: full contents of the selected files + issue title and body

**Expected output:**
```json
[
  {
    "path": "README.md",
    "action": "modify",
    "content": "...full new file content..."
  },
  {
    "path": "playbooks/new_playbook.yml",
    "action": "create",
    "content": "---\n..."
  }
]
```

`action` is `"modify"` for existing files or `"create"` for new files. The script validates that `"modify"` paths exist in the repo before writing.

### File Writing

- `"modify"` paths that don't exist are skipped (warning logged)
- `"create"` paths are written freely, including creating parent directories
- If no files end up written, the script posts a comment on the issue and exits 0 (no PR opened)

---

## Error Handling

| Failure | Behaviour |
|---|---|
| Call 1 returns empty list | Post issue comment asking for more detail; exit 0 |
| Call 2 returns invalid JSON after one retry | Post issue comment; exit 0 |
| `"modify"` path missing from repo | Skip that file; apply others |
| No files written after all edits | Post "No changes generated" comment; exit 0 without opening PR |
| `OPENAI_KEY` not set | Exit 1 (workflow fails visibly — config error) |
| PR creation fails | `gh pr create` exits non-zero; workflow fails visibly |

## PR Format

- **Title:** `ai: {issue title}`
- **Body:** `Closes #{issue_number}\n\nGenerated by AI based on issue description. Please review all changes carefully before merging.`
- **State:** Draft

---

## Branch Naming

`ai-issue-{number}-{slugified-title}`

Slug: lowercase, spaces and special chars replaced with `-`, truncated to 50 chars.
